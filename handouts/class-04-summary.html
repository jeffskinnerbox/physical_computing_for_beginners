Meet the Hardware

LSM9DS1: Three Sensors on One Board

“9-DOF” means nine degrees of freedom — three sensors, each measuring along x, y, and z. It talks to the Pico over I2C: two wires (SDA data, SCL clock) that many sensors can share.

Accelerometer

Measures linear acceleration — always including gravity. At rest it points straight at the floor, which is how it senses tilt.

Weakness: noisy under vibration and bumps.

Gyroscope

Measures angular rate — how fast the board is rotating, in radians per second — not an angle.

Weakness: small errors add up into drift.

Magnetometer

A compass — an absolute heading reference.

Not used today — Class 5 adds it to steer the rover.

The Language of Orientation

Roll, Pitch, and Yaw

Z (yaw axis) ^ | YAW = turning flat, | like steering the car | +-----------> X (roll axis) / ROLL = tipping onto / one side v Y (pitch axis) PITCH = nose up / nose down
  • Roll spins around X, pitch around Y, yaw around Z.
  • Inside the filter, orientation is stored as a quaternion (q0..q3) — a compact form that avoids gimbal lock.
  • It's converted to roll/pitch/yaw degrees only for printing — the numbers humans can read.
The Core Problem

Neither Sensor Is Good Enough Alone

Accelerometer only

  • Knows which way is down — right on average, over time
  • But a moving car shakes it constantly, with forces that have nothing to do with tilt
  • Result: jumpy, noisy angles moment to moment

Gyroscope only

  • Smooth and fast — great for moment-to-moment changes
  • But it measures rate, so you add it up (integrate) to get an angle
  • Every tiny error gets added up too: the angle slowly drifts even when the board never moves

Fuse them

  • Trust the gyro for fast changes
  • Keep nudging toward the accelerometer over the long term
  • Get the gyro's smoothness without its drift, and the accelerometer's truth without its noise
Sensor Fusion

The Mahony Filter, Every Loop

gyroscope running estimate (rotation rate) ---> [ + correction ] ---> integrate over dt ---> [ quaternion q0..q3 ] ^ | | v error x MAHONY_KP "where I THINK down is" + MAHONY_KI running total | | | +------+------+ | accelerometer ----> | COMPARE | <-------------------------------------+ ("where down +-------------+ REALLY is") the mismatch is the error that pulls the drift back out

Tune it live: MAHONY_KP

Too low → drift creeps in. Too high → jitter. You'll feel the tradeoff.

Other ways to fuse

Kalman and Madgwick filters solve the same problem with different math.

Phase 3 — The Problem

Why Yaw Drifts (and the Filter Can't Fix It)

Every gyroscope has a bias — a small reading even when it isn't rotating. Different on every chip, and it shifts as the chip warms up.

bias 0.5 deg/s, added up every loop: after 10 s -> 5 deg after 30 s -> 15 deg after 60 s -> 30 deg of error (board never moved!)

Down doesn't change when you turn

Roll or pitch wander → “down” looks different → the filter sees the mismatch and pulls it back.

Turn the board flat on the table → “down” is exactly the same → the accelerometer has no opinion about yaw. Nothing corrects it.

Phase 3 — The Fix

Stop the Bias Before It Reaches the Filter

1. Startup calibration

  • Hold the board still for ~2 seconds and average the gyro
  • It isn't rotating, so that average is the bias
  • Subtract it from every reading from then on

2. Keep refining when still

  • Gyro reads almost nothing and the accelerometer feels just gravity (~1 g)?
  • Then what's left must be bias — nudge the estimate 1% toward it
  • A rover that stops often gets re-trimmed at every stop
raw gyro ---> [ subtract bias ] ---> [ is_still()? ] ---> Mahony filter ^ | | | yes, still +----------------------+ bias += 1% of what's left, and clear the filter's integral term

The tradeoff: a turn slower than ~1°/s (STILL_GYRO) looks exactly like bias and gets absorbed. Fine for a car — it turns far faster than that.

Phase 3 — One More Leak

Shake It Hard, Set It Down… Still Drifting?

The filter's own integral term piles up errors while you shake the board — engineers call it windup.

SHAKING SET DOWN FOREVER AFTER accel "down" roll/pitch integral_fbz never is wrong --> errors unwind unwinds (accel can't totals pile up x, y totals see yaw) --> a FAKE bias, drifting yaw

Fix 1: MAHONY_KI = 0.0

One number. No integral term, so no windup — simplest.

Fix 2: clear it when still (used)

MAHONY_KI helps while moving; the bias estimate takes over at rest.

Neither puts yaw back — they make it stop changing within a couple of seconds.

Looking Ahead

Knowing which way you're pointed still isn't the same as knowing how far you've traveled.

Even with wheel speed and orientation side by side on one webpage, the IMU alone doesn't solve Class 3's square-and-circle problem. So Class 5 navigates by sweeping the sensor and servo from Class 2 to find open space — and adds the IMU's magnetometer so a drift-free compass heading steers every turn.
